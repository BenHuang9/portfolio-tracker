Portfolio 5.21.3 - Test scope and observed results

Baseline: supplied portfolio_scroll_recovery_v5_21_2.zip.

Reproduced failure in 5.21.2:
Hold 350ms, move horizontally 18px, then move downward 145px without lifting.
The page moved 0px. The chart cancelled 11 touchmove events.

Same gesture in 5.21.3:
393px viewport: page moved upward 101px during the gesture, then continued
with native momentum. No touch event was cancelled.
320px viewport: page moved upward 102px during the gesture. No touch event
was cancelled.

Checks:
- Direct down/up drag after a stationary hold (350ms and 1200ms).
- Small horizontal wobble before vertical intent.
- Stationary reading, horizontal reading and touch release.
- Wealthsimple 1D (minute-data fixture) and ALL (daily-data fixture).
- Questrade TFSA 1M, Questrade Cash 1D, CIBC 1D/ALL, Home and bank detail.
- Touch cancellation, subsequent navigation and absence of leaked busy state.
- Cash Balance save and unchanged lots, transactions and deposits.
- No non-passive touchmove listener on the charts.
- No page horizontal overflow at 320px and 393px.
- No runtime errors, no real market calls, no real cloud writes.
- Nineteen calculation/save/sync functions compared source-identical to 5.21.2.
- JavaScript syntax checks: inline application script and service worker pass.

40 checks passed across 320/393px daily fixtures. The repeated 393px suite
with the primary Investment view set to 1D passed 20 checks.

IMPORTANT TEST BOUNDARY:
The "inspect_then_down" check verifies no app cancellation, cleanup and a
working NEXT vertical gesture. It does not claim immediate vertical movement
after an 80px horizontal gesture. Chromium direction-rails that existing
horizontal gesture even with no app preventing touch events. The next vertical
gesture moved 130px; no scroll/page lock remained.

Environment:
System Chromium through Playwright/CDP touch input. Full supplied application
HTML, isolated memory localStorage, mocked quotes/NAV, cloud sync disabled.
Navigation is sandboxed; tests use set_content, not the deployed site.
WebKit could not be installed (download DNS unavailable). No physical iPhone,
iOS Safari or installed PWA verification has been performed. UI display files
are prepared only; no deployment to the user's GitHub/Cloudflare was made.
